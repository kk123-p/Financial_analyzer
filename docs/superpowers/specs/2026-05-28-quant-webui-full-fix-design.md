量化模块（quant/）有四个主要功能：信号生成、回测分析、敏感性分析、模拟交易。信号生成和回测分析已有前端 UI 且基本可用，敏感性分析和模拟交易缺少前端 UI。本次迭代目标是全面排查修复所有功能，确保四个功能在 Web UI 上都能正常工作。

## 修复方案

### 循环 2：敏感性分析（后端 + 前端）

**目标：** 创建完整的敏感性分析功能

**后端 API 设计：**

量化敏感性分析 = **因子权重敏感性**：分析当因子权重变化时，策略收益如何变化。
（注意：这与 `calculator/scenario.py` 中的 DCF 敏感性分析不同，后者是估值层面的。）

新增端点 `POST /api/v1/quant/sensitivity`：
- 请求参数：
  - `pool`: 选股池名称（如 "沪深300"）
  - `factor_x`: X 轴因子名称（如 "roe"）
  - `factor_y`: Y 轴因子名称（如 "pe"）
  - `variation_range`: 变化范围，默认 ±50%（即权重乘以 0.5~1.5）
  - `steps`: 采样步数，默认 5（生成 5×5 矩阵）
- 返回：异步任务 ID（复用 task_store 模式）
- 实现逻辑：对每组因子权重组合，运行完整的因子矩阵 → 标准化 → 打分 → 排名 → 信号生成流程，计算最终策略收益

新增端点 `GET /api/v1/quant/sensitivity/status/{task_id}`：
- 复用现有的 task_store 轮询模式

新增端点 `GET /api/v1/quant/sensitivity/result/{task_id}`：
- 结果包含：
  - `matrix`: 二维数组，行=因子 X 权重变化，列=因子 Y 权重变化，值=策略收益（%）
  - `x_labels`: X 轴标签（权重值）
  - `y_labels`: Y 轴标签（权重值）
  - `base_return`: 基准收益（原始权重）
  - `best_params`: 最优参数组合
  - `worst_params`: 最差参数组合

**前端 UI 设计：**

┌─────────────────────────────────────────────────┐
│  敏感性分析                                       │
│                                                   │
│  参数设置:                                         │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ 因子 X    │ │ 因子 Y    │ │ 变化范围  │          │
│  └──────────┘ └──────────┘ └──────────┘          │
│  [运行分析]                                        │
│                                                   │
│  结果展示:                                         │
│  ┌─────────────────────┐ ┌──────────────────┐    │
│  │    热力图            │ │   参数对比表      │    │
│  │  (ECharts heatmap)  │ │                  │    │
