# AI 财务分析模块 UX 优化 — 设计说明

## 背景

Phase 2 AI 分析模块已完成核心功能（PromptFramework / OutputParser / ConversationManager / AnalysisOrchestrator / WebSocket 对话 API / 统一聊天面板 / 辩论 Tab）。当前存在三个 UX 痛点：

1. **数据与 Prompt 耦合** — 分析框架模板硬编码在 Python 字符串中，用户无法查看、编辑或切换不同的分析策略
2. **数据不可见** — 第一阶段的财务体检报告作为 AI 输入被"吞掉"，用户无法独立查看或导出
3. **辩论布局拥挤** — 三方辩论内容在单个滚动区域线性堆叠，缺乏空间分区，交互性弱

## 目标

### 需求 1：Prompt 工程实验室

将分析框架模板从代码中解耦，提供用户可编辑、可保存、可切换的 Prompt 模板管理系统。

### 需求 2：数据与 Prompt 查看

在 AI 投研 Tab 增加两个按钮，分别可查看第一阶段财务数据报告和当前使用的 Prompt 模板。

### 需求 3：辩论 UI 重布局

三方辩论区域重新设计为三列独立发言区 + 总结区 + 追问栏的四区域布局，并支持导出。

## 模块 1：Prompt 工程实验室

### 存储设计

Prompt 模板以 JSON 文件存储于 `~/.financialanalyzer/prompts/` 目录：

```
~/.financialanalyzer/prompts/
├── _default_deep.json      # 系统预置深度分析模板（不可删除）
├── _default_quick.json     # 系统预置快速问答模板（不可删除）
├── my_custom_1.json        # 用户自定义模板
└── my_custom_2.json        # 用户自定义模板
```

系统预置模板以 `_` 前缀标识，不可删除但可复制修改。

### 模板数据结构

```json
{
  "name": "深度分析-默认",
  "description": "包含哈佛分析、三表联动、生命周期、预警清单的完整深度分析框架",
  "mode": "deep",
  "system_role": "你是一位拥有20年经验的高级财务分析师...",
  "frameworks": {
    "harvard": "## 哈佛分析框架\n\n### 1. 战略分析\n...",
    "crosscheck": "## 三表联动验证\n...",
    "lifecycle": "## 生命周期定位\n...",
    "warnings": "## 利润质量恶化预警清单\n..."
  },
  "output_format": "## 输出格式要求\n\n📊 数据依据\n...\n🔍 推理过程\n...\n✅ 综合结论\n...",
  "created_at": "2026-05-21T12:00:00",
  "updated_at": "2026-05-21T12:00:00"
}
```

### 后端 API

**新增文件：** `financial_analyzer/ai/prompt_store.py`

PromptsStore 类，负责模板的 CRUD 和文件读写：

- `list_templates()` → 列出所有模板（名称 + 描述）
- `get_template(name)` → 获取单个模板完整内容
- `save_template(name, data)` → 创建或更新模板
- `delete_template(name)` → 删除模板（系统预置不可删）
- `duplicate_template(source_name, new_name)` → 复制模板
- `export_template(name)` → 导出为 JSON 字符串
- `import_template(json_str)` → 从 JSON 字符串导入

**新增 API 端点（`web/routes/ai_api.py`）：**

| 端点 | 方法 | 说明 |
|------|------|------|
| `/ai/prompts` | GET | 列出所有模板（name + description） |
| `/ai/prompts/{name}` | GET | 获取单个模板完整 JSON |
| `/ai/prompts/{name}` | PUT | 保存/更新模板 |
| `/ai/prompts/{name}` | DELETE | 删除模板 |
| `/ai/prompts/{name}/duplicate` | POST | 复制模板 |
| `/ai/prompts/export/{name}` | GET | 导出模板 JSON 文件下载 |
| `/ai/prompts/import` | POST | 导入模板（上传 JSON 文件） |

### PromptBuilder 改造

修改 `financial_analyzer/ai/prompt_framework.py`：

- `PromptBuilder` 新增 `with_template(template_dict)` 方法
- 当传入模板时，框架内容从模板 JSON 的 `frameworks` 字段加载，而非 Python 常量
- 保留硬编码常量作为 fallback（未选择模板时使用）

### 前端 UI

AI 投研 Tab 输入区增加模板选择器和编辑入口：

```
┌──────────────────────────────────────────────────┐
│ [模板: 深度分析-默认 ▾] [📝 编辑]  [📊 查看数据] │
│ [输入框................................] [发送]  │
└──────────────────────────────────────────────────┘
```

- **下拉选择器** — 切换当前使用的 Prompt 模板，切换后立即生效
- **📝 编辑按钮** — 打开 Prompt 编辑模态弹窗

**Prompt 编辑模态弹窗：**

```
┌──────────────────────────────────────────┐
│ 编辑 Prompt 模板                    [×]   │
│                                          │
```

## 模块 3：辩论 UI 重布局

### 布局结构

```
┌──────────────────────────────────────────────────┐
│ [▶ 开始辩论]  第1轮：独立陈述    辩论进行中...   │  ← 控制栏
├──────────────┬──────────────┬────────────────────┤
│ 📊 格雷厄姆  │ 🚀 费雪     │ 🛡️ 塔勒布         │  ← 三列独立
│   价值派     │   成长派     │   风控派           │    滚动区
│              │              │                    │
│ Round 1:     │ Round 1:     │ Round 1:           │
│ 独立陈述...  │ 独立陈述...  │ 独立陈述...        │
│              │              │                    │
│ Round 2:     │ Round 2:     │ Round 2:           │
│ 交叉质询...  │ 交叉质询...  │ 交叉质询...        │
│              │              │                    │
│ 追问1:       │ 追问1:       │ 追问1:             │
│ 用户追问回复 │ 用户追问回复 │ 用户追问回复       │
├──────────────┴──────────────┴────────────────────┤
│ 📋 综合共识与情景概率                            │  ← 总结区
│                                                  │
│ 核心共识：盈利质量优秀（三方一致）| 估值存在分歧  │
│ 🟢 乐观 40% → +15%  🟡 中性 35% → ±5%          │
│ 🔴 悲观 25% → -20%                              │
├──────────────────────────────────────────────────┤
│ 💬 追问三方：[输入框......................]       │  ← 追问栏
│ [发送追问] [停止]         [导出Markdown] [导出HTML]│
└──────────────────────────────────────────────────┘
```

### 各区域说明

**控制栏：**
- 「开始辩论」按钮 — 点击后调用 `/ai/debate` WebSocket（保留旧端点）
- 辩论进行中按钮变为禁用状态，显示"辩论中..."
- 实时显示当前轮次（第1轮：独立陈述 / 第2轮：交叉质询 / 第3轮：共识与情景概率）
- 辩论结束后按钮恢复为"重新辩论"

**三列分析师区：**
- 三列等高，各自独立滚动
- 每列有固定的分析师名称头部（带颜色标识）
- 每个 chunk 消息根据 `role` 字段路由到对应列
- 内容按轮次分段，每个轮次前有小的轮次标签
- 追问回复追加到对应列末尾

**总结区：**
- 第3轮 consensus 角色的流式输出显示在此区域
- 辩论结束后完整展示综合共识 + 情景概率分布

**追问栏：**
- 辩论结束后（或暂停状态下）可用
- 输入框 + 「发送追问」按钮
- 追问消息通过 WebSocket 发送，三方生成回复
- 「停止」按钮中断当前追问

**导出按钮：**
- 「导出 Markdown」— 下载 `.md` 文件，用标题层级组织三方发言
- 「导出 HTML」— 下载 `.html` 文件，保留三方颜色标识和完整排版，浏览器直接打开

### WebSocket 消息协议

辩论 WebSocket (`/ai/debate`) 消息格式：

```json
// 控制元信息
{"type": "meta", "content": "round1_start"}
{"type": "meta", "content": "analyst_value_start"}
{"type": "meta", "content": "analyst_value_done"}

// 分析师文本块（前端根据 role 路由到对应列）
{"type": "chunk", "role": "value", "content": "...", "done": false}
{"type": "chunk", "role": "growth", "content": "...", "done": false}
{"type": "chunk", "role": "risk", "content": "...", "done": false}
{"type": "chunk", "role": "consensus", "content": "...", "done": false}

// 辩论结束
{"type": "done", "content": ""}

// 错误
{"type": "error", "content": "错误信息"}
```

现有 `/ai/debate` WebSocket 已使用此消息格式，前端需调整路由逻辑。

## 风险控制

- **向后兼容** — 硬编码框架模板保留作为 fallback，无模板时行为不变
- **预置模板不可删** — `_` 前缀的模板文件受保护
- **辩论独立** — 辩论 UI 改动仅影响 `tab-debate`，不影响其他 Tab
- **旧 WebSocket 保留** — `/ai/debate` 端点消息格式不变，只改前端渲染逻辑
- **模板文件损坏** — 每个模板独立 JSON 文件，单个损坏不影响其他
