# 量化模块 Web UI 调试与修复 — 设计规格

## 概述

量化模块（quant/）已开发的功能在 Web UI 上大部分无法正常工作。前端代码 `quant.js`（2014 行）包含了所有功能的实现，但用户报告只有信号生成能用。需要系统排查并修复所有问题。

## 问题现状

### 已有代码
- `frontend/js/quant.js` — 2014 行，包含所有功能的前端逻辑
- `frontend/css/quant.css` — 872 行，包含所有功能的样式
- 后端 API 路由已注册：`quant_api.py`、`backtest_api.py`、`paper_trading_api.py`

### 用户报告
- 只有信号生成功能可用
- 回测、敏感性分析、模拟交易等功能在 UI 上不显示或不工作

### 可能原因
1. **JavaScript 运行时错误** — IIFE 内任何错误会导致整个文件停止执行
2. **API 端点问题** — 路由未正确注册或返回错误
3. **CSS 布局问题** — 面板被隐藏或样式错误
4. **依赖加载问题** — `$` 函数或 `window.__app` 未正确加载

## 调试方法

### 步骤 1：启动 Web 服务器
```bash
# 运行 run_web.bat 或
python run_web.py
```
访问 http://127.0.0.1:8000

### 步骤 2：检查浏览器控制台
- 按 F12 打开开发者工具
- 查看 Console 标签页的错误信息
- 记录所有 JavaScript 错误

### 步骤 3：逐功能测试
1. **信号生成** — 用户报告可用，验证是否正常
2. **回测分析** — 点击"运行回测"按钮，检查是否显示结果
3. **敏感性分析** — 点击"运行分析"按钮，检查是否显示结果
4. **模拟交易** — 点击"初始化"按钮，检查是否显示持仓

### 步骤 4：检查网络请求
- 在开发者工具的 Network 标签页查看 API 请求
- 检查请求是否成功（200 状态码）
- 检查响应数据是否正确

## 预期问题与修复方案

### 问题 1：JavaScript 运行时错误
**症状**：控制台显示错误，quant.js 无法执行
**修复**：定位错误行号，修复语法或逻辑错误

### 问题 2：API 调用失败
**症状**：网络请求返回 404 或 500 错误
**修复**：检查后端路由注册，修复 API 端点

### 问题 3：UI 不显示
**症状**：面板存在但内容为空
**修复**：检查渲染函数，修复 DOM 操作

### 问题 4：功能不响应
**症状**：按钮点击无反应
**修复**：检查事件绑定，修复监听器

## 验证标准

修复完成后，以下功能必须正常工作：

1. **信号生成** — 选择选股池，点击"生成信号"，显示调仓信号列表
2. **回测分析** — 设置日期范围，点击"运行回测"，显示绩效指标和图表
3. **敏感性分析** — 设置参数，点击"运行分析"，显示热力图和对比表
4. **模拟交易** — 点击"初始化"，显示持仓列表；点击"执行信号"，显示交易记录

## 技术约束

- 保持现有代码架构不变
- 不引入新的依赖
- 修复必须向后兼容
- 每个修复单独提交，便于追踪

## 开发阶段

### 循环 1：调试与问题识别
- 启动 Web 服务器
- 检查浏览器控制台错误
- 逐功能测试，记录所有问题
- 生成问题清单

### 循环 2-N：逐个修复
- 按优先级修复问题
- 每个修复后验证功能
- 提交修复代码
